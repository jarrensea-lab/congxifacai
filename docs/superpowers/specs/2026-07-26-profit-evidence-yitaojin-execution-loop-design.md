# 盈利证据与易淘金执行闭环设计

日期：2026-07-26
状态：待用户最终复核
目标：把历史研究、策略验证、生产标的池、广发易淘金真实账户、自选股展示和实际成交归因连接成一个以成本后净利润为最终评价标准的闭环。

本设计整合并扩展 `2026-07-24-profit-truth-optimization-design.md`：保留运行版本真值、持仓风控对账、亏损冷却、数据新鲜度和人工确认边界，新增历史数据研究、易淘金账户读取、自选股同步、准实时行情校验和真实成交归因。

## 1. 成功标准

本轮不以新增报告、模型数量或交易次数作为成功标准。完成后必须满足：

1. 易淘金真实持仓、现金和成交能够进入项目的账户真值链，项目快照不再长期滞后。
2. 历史策略只能通过符合 A 股交易约束的样本外验证晋级，旧简化回测不能决定资金动作。
3. 易淘金“自选股”稳定显示：用户手工自选、`executable`、`watching` 和当前真实持仓。
4. `research_reference`、`removed`、`expired` 不进入生产自选股；持仓股即使退出标的池仍保留。
5. 系统只能移除自己添加的自选股，不能删除用户原有或后来手工添加的股票。
6. 盘中只针对持仓和有效候选读取易淘金准实时行情，并在关键动作前二次核价。
7. 每个真实成交能够关联策略、信号、建议、实际价格、费用和最终盈亏；无法证明的历史成交保持未归因。
8. 不保存交易密码、验证码或完整账户号，不自动下单，不修改易淘金内部数据库。

## 2. 系统边界

易淘金在本设计中承担两个角色：

- **账户事实源**：读取持仓、现金、历史成交和费用。
- **执行展示与行情校验端**：展示有效候选和持仓，提供有限标的的准实时行情。

易淘金不承担以下角色：

- 不作为全市场历史研究数据源。
- 不作为未经验证策略的晋级依据。
- 不提供自动委托、清仓、转账或密码托管。
- 不通过逆向私有接口或直接修改客户端数据文件完成同步。

历史研究继续使用已登记的分时数据和复权因子；生产决策继续由项目的证据门、账户门和风险门共同决定。

## 3. 总体架构

```text
历史分时数据 + 复权因子
  -> 数据质量门 + 历史时点股票池
  -> 真实 A 股执行模拟
  -> Walk-forward / 样本外验证 / 多重试验修正
  -> 策略证据生命周期
  -> Target Pool
  -> executable + watching
  -> 易淘金自选股同步
  -> 用户人工确认交易
  -> 易淘金真实成交与费用
  -> 执行归因与成本后净利润
  -> 策略晋级、降级或淘汰

易淘金真实持仓
  -> 项目持仓对账
  -> 持仓风控与每日操作计划
  -> 易淘金自选股保留
```

自选股同步只是生产结果的投影层，不能反向把“已加入自选”解释为买入授权。

## 4. 核心组件

### 4.1 可信研究引擎

- 历史压缩包原地保存，建立轻量清单、覆盖率检查和按需缓存。
- 保存历史日期对应的真实股票池，避免幸存者偏差。
- 执行模拟必须覆盖下一可交易时点成交、T+1、涨跌停、停牌、100 股整数手、佣金、印花税、过户费和滑点。
- 使用真实资金曲线计算复利收益、回撤、夏普率、Profit Factor 和成本后期望。
- 所有参数尝试必须登记；策略选择使用 Walk-forward、配对比较和多重试验修正。
- 旧简化回测器保留为冒烟测试，不得用于策略晋级。

### 4.2 易淘金账户读取器

- 目标应用固定为 `/Applications/GF-Trader.app`。
- 通过正常界面读取总资产、可用资金、冻结资金、持仓数量、成本、市值、浮动盈亏、历史成交和资金流水。
- 账户绑定只保存本地不可逆指纹，不写入完整账户号、手机号或股东账号。
- 读取结果先进入隔离快照，经结构校验和差异检查后才能更新项目账户真值。
- 持仓读取为空、资产突变超阈值或账户指纹不一致时，失败关闭，不覆盖旧真值。

### 4.3 易淘金行情校验器

抓取范围固定为：

```text
当前真实持仓 ∪ executable ∪ watching
```

运行规则：

- 盘中与现有生命周期扫描同步，每 5 分钟读取一次。
- 08:55、11:35、14:55执行重点校验。
- 买入、加仓、止损或止盈动作展示前，必须再次读取最新报价。
- 每条记录包含代码、行情时间、现价、涨跌幅、成交量、成交额、最高、最低、昨收、数据完整性和抓取延迟。
- 常规扫描行情超过 90 秒视为过期；关键动作前行情超过 30 秒视为过期。
- 与另一生产行情源在相近时间戳下偏差超过配置阈值时，标记冲突并禁止新开仓。

行情校验器只提高执行时点的数据可信度，不替代历史数据，也不单独生成买卖信号。

### 4.4 自选股同步规划器

期望集合定义为：

```text
用户手工自选 ∪ executable ∪ watching ∪ 当前真实持仓
```

规划器输出：

- `add`：应存在但当前缺失的系统管理股票。
- `remove`：系统曾添加、已不在有效池、且当前不持仓的股票。
- `keep`：仍有效、仍持仓或受手工保护的股票。
- `blocked`：因账户、行情、客户端或数据异常而禁止执行的变更。

规划器是纯数据模块，不直接操作易淘金，必须支持 `dry-run`。

### 4.5 自选股界面执行器

- 只使用易淘金正常界面完成添加和移除。
- 首次启用时把现有自选股全部登记为 `manual_protected`。
- 系统维护独立的 `managed_codes` 所有权账本，只删除账本中由系统添加的代码。
- 手工自选与系统候选重合时仍按手工保护处理。
- 持仓优先级最高，退出标的池后仍保留。
- 首次三次同步采用只新增模式；连续成功后才启用受控移除。
- 移除必须连续两次确认“已退出有效池且不持仓”，避免短暂数据故障造成误删。
- 不重排用户原有自选股；系统新增项追加显示。

同步计划：

- 20:45：日报和标的生命周期完成后同步。
- 08:55：盘前校准后同步。
- 支持人工触发 `dry-run` 和“立即同步”。
- 易淘金未运行时允许启动客户端；未登录或账号锁定时记录待同步，不输入密码。

状态和审计数据保存在项目运行状态目录，不进入 Git：

```text
~/Library/Application Support/congxicai-v7/yitaojin_watchlist_state.json
~/Library/Application Support/congxicai-v7/yitaojin_sync_audit.jsonl
```

### 4.6 真实执行归因

- 每条生产建议携带 `strategy_id`、`signal_id`、`recommendation_id` 和目标交易日。
- 易淘金真实成交记录通过代码、方向、时间、数量和价格做确定性匹配。
- 匹配不唯一时保持未归因，不根据最终盈亏倒推信号身份。
- 策略评价使用真实费用后的净收益、最大回撤、Profit Factor、收益集中度和样本外稳定性。
- 策略实际表现跌破门槛时自动降级到影子模式，但不自动执行卖出。

## 5. 错误处理与失败关闭

- 易淘金未登录、账户指纹不一致：不读写账户数据，不修改自选股。
- 持仓读取为空或资产数据不完整：保留旧快照，禁止所有删除。
- 标的池文件损坏或时间戳过期：不修改自选股。
- 行情过期或多源价格冲突：允许风险提示，禁止新的买入和加仓展示。
- 添加单只股票失败：记录失败并继续其他新增，不执行删除阶段。
- 移除单只股票失败：保留所有权记录，下次重试。
- 易淘金界面版本变化或目标元素无法识别：整轮同步失败关闭，不使用坐标盲点操作交易区域。
- 任何同步异常都不能进入买入、卖出、一键清仓或转账页面。

## 6. 实施阶段与预期成效

### P0：真值修复

- 修复复盘异常写入零收益的问题。
- 对齐运行版本、磁盘代码和常驻服务身份。
- 完成易淘金账户读取、隔离快照和持仓差异报告。

预期：项目不再基于过期持仓和错误收益反馈继续学习。

### P1：安全自选股同步

- 实现纯规划器、所有权账本、`dry-run` 和只新增试运行。
- 连续三次验证无误后，启用双确认受控移除。
- 接入08:55和20:45调度。

预期：每天打开易淘金即可看到手工自选、有效候选和真实持仓，且手工自选零误删。

### P2：可信回测与策略淘汰

- 建立数据清单、历史时点股票池和真实 A 股执行模拟。
- 对少量可解释策略进行固定预算的样本外淘汰赛。

预期：淘汰大部分伪策略；没有策略通过时明确不晋级。

### P3：准实时行情校验

- 对持仓和有效候选进行每5分钟行情读取。
- 在关键动作展示前强制二次核价。
- 与现有生产行情源交叉验证。

预期：减少外部数据超时、价格偏离、涨跌停或停牌状态未识别造成的错误操作。

### P4：影子验证与有限实盘

- 候选策略先运行20至40个交易日影子验证。
- 只有成本后正期望、覆盖率和样本量达标，且用户明确批准亏损预算后，才设计小额人工确认试验。

预期：能够回答策略是否存在真实样本外优势；不能承诺固定收益率。

## 7. 测试与验收

### 单元测试

- 状态到自选股集合的映射。
- 手工保护、系统所有权、持仓优先和双确认移除。
- 空持仓、过期池、账户不一致和行情冲突的失败关闭。
- 重复运行幂等，不重复添加、不误删。
- 成交匹配唯一性和未归因边界。

### 集成测试

- 使用易淘金界面结构的脱敏固定样本验证解析器。
- 使用临时候选池和临时状态目录执行 `dry-run`。
- 验证客户端关闭、未登录、页面变化和部分添加失败。
- 验证同步操作不会访问委托、清仓和转账页面。

### 生产验收

1. 首次运行只生成差异报告，不修改自选股。
2. 首次应用只新增，不删除。
3. 连续三次同步结果与人工核对一致。
4. 人工制造一个系统候选退出，验证双确认后正确移除。
5. 人工自选和持仓在任何情况下都不被删除。
6. 同步审计记录能够完整解释每次新增、保留、阻断和移除。
7. 全量 pytest、Ruff 和隔离报告验证通过。

## 8. 明确不做

- 不自动下单、撤单、清仓或转账。
- 不保存、填写或代理输入交易密码和验证码。
- 不直接修改易淘金内部数据库或逆向私有接口。
- 不把 `research_reference` 批量加入生产自选股。
- 不抓取全市场高频行情。
- 不因为增加行情源而放宽策略晋级门槛。
- 不在证据不足时承诺收益率。

## 9. 必须暂停的条件

- 需要扩大到自动委托或资金权限。
- 需要保存或使用交易凭证。
- 易淘金界面无法稳定区分自选操作与交易操作。
- 账户真值无法核验或出现不可解释的资产差异。
- 自选股同步存在误删手工股票的可能。
- 真实服务重启目标和当前运行进程无法证明一致。
- 全量回归出现无法安全修复的失败。
