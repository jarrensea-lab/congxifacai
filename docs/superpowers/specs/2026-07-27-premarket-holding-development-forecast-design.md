# 盘前持仓发展预测设计

日期：2026-07-27  
状态：用户已确认推荐方案，待实现计划  
目标：在盘前主报告中增加可执行、可复盘的持仓发展预测，同时保持持仓动作、硬止损和账户真值的最高优先级。

## 1. 用户可见结果

盘前报告的“二、明日持仓策略”保留现有动作表，并在其后增加：

### 飞书精简版

- 每只持仓显示：短期方向、基准观察区间、关键验证信号、风险边界。
- 增加组合三情景摘要：悲观、基准、乐观情景下的组合市值变化范围。
- 整个模块继续位于 `FEISHU_SUMMARY_END_MARKER` 之前，但必须满足飞书摘要 3000 字限制。

### Obsidian 详细版

- 保留飞书精简表。
- 在审计区增加预测口径、输入数据时间、缺失字段、情景计算结果和预测失效条件。
- 明确区分“账户/行情事实”“规则计算”“模型或策略推断”。

## 2. 方案比较

### 方案 A：直接展示 AI 自由文本预测

优点是表达丰富，容易覆盖基本面、题材和市场情绪。缺点是价格区间、方向和风险动作难以验证，AI 文案可能与止损表冲突，也不便于复盘统计。

结论：不采用。

### 方案 B：确定性情景框架，预测文案受结构化字段约束

使用真实持仓、有效收盘价、成本、止损、目标位、组合现金和风险等级生成情景框架。方向、区间和信号必须由结构化字段产生；如果输入不完整，报告明确写出具体缺失项。

优点是与现有持仓真值和硬风控链兼容，可测试、可复盘，也能稳定进入飞书摘要。

结论：本轮采用。

### 方案 C：单独建设概率预测模型后再接报告

优点是未来可以给出概率、置信区间和历史命中率。缺点是当前预测账本尚不足以证明概率校准有效，会扩大本轮范围。

结论：保留为后续迭代；本轮先沉淀结构化预测样本。

## 3. 报告结构

不新增顶级编号，避免破坏现有“一至四”主报告和飞书契约。在“二、明日持仓策略”动作表后增加三级标题：

```markdown
### 持仓发展预测

| 持仓 | 短期方向 | 基准观察区间 | 关键验证信号 | 风险边界 |
|---|---|---:|---|---|
```

表后增加一行组合情景：

```text
组合情景：悲观 ...；基准 ...；乐观 ...。情景用于盘前预案，不是收益承诺。
```

若任一持仓已经触发止损，模块首行必须写明“硬止损已触发，预测失效”，且不得用乐观情景弱化退出动作。

## 4. 数据契约与优先级

### 4.1 事实输入

每只持仓只使用以下可审计输入：

- `user_portfolio.json`：代码、名称、股数、成本、当前价、市值。
- `position_watch.json`：止损价、目标价、来源和更新时间。
- 报告服务日对应的行情状态：来源、时间、新鲜度、交易日。
- 报告级风险等级、可用现金和总资产。

### 4.2 派生字段

新增内部结构 `holding_forecast`：

```python
{
    "code": "000100",
    "direction": "修复观察",
    "base_low": 4.80,
    "base_high": 5.40,
    "key_signal": "站稳关键验证位后才上调预期",
    "risk_boundary": 4.54,
    "scenario_basis": "有效收盘价 + 成本 + 止损/目标 + 报告风险等级",
    "data_status": "complete",
}
```

这些字段是规则计算结果，不写回真实持仓文件。本轮不让自由文本 AI 直接决定止损、目标或预测区间。

### 4.3 优先级

从高到低：

1. 新鲜行情下已经触发的硬止损或止盈动作。
2. 行情缺失、陈旧、冲突等数据报警。
3. 现有持仓动作表。
4. 持仓发展预测和组合情景。

低优先级内容不得覆盖高优先级结论。

## 5. 预测规则

### 5.1 方向分类

- `风险退出`：有效价格不高于止损。
- `目标兑现`：有效价格不低于目标。
- `弱势修复`：价格高于止损但低于成本，且距离止损小于距离目标。
- `修复观察`：价格接近成本，尚未突破关键验证区。
- `偏强持有`：价格高于成本且未触及目标。
- `数据待核验`：行情、成本、止损或目标任一关键输入不可审计。

方向只是状态分类，不替代买卖动作。

### 5.2 基准观察区间

- 区间必须位于有效止损与目标位之间。
- 当前价是区间锚点；风险等级越高，区间上沿越保守。
- 若存在可审计的近期波动尺度，优先使用波动尺度计算区间，并裁剪到止损/目标边界。
- 若缺少可审计波动尺度，降级使用止损—当前价—目标位构造“规则观察带”，并在审计区标注“非统计置信区间”。
- 价格精度按 A 股常用两位小数输出。

实现计划必须把区间公式写成独立纯函数并用边界测试锁定，不能把公式散落在 Markdown 拼接代码中。

### 5.3 关键验证信号

关键验证信号必须来自可计算价格节点：

- 弱势仓：先看成本价收复，再看目标位。
- 盈利仓：看当前价附近支撑是否保持，再看目标位。
- 接近止损：只显示止损和禁止补仓，不生成“逢低吸纳”措辞。
- 数据异常：显示需要补齐的具体行情字段，不生成方向判断。

### 5.4 组合三情景

- 悲观情景：各持仓按止损边界估值，加上现金。
- 基准情景：各持仓按基准观察区间估值，加上现金，输出组合变化范围。
- 乐观情景：各持仓按目标边界估值，加上现金。
- 百分比以当前总资产为分母，同时显示金额和百分比。
- 已触发止损的持仓不参与乐观延续叙事；其执行结论仍为退出。

三情景是盘前压力测试，不是概率预测或收益承诺。

## 6. 错误处理

- 缺当前价：该持仓显示“行情缺失，无法预测”，组合情景不静默使用成本代替现价。
- 行情陈旧或来源冲突：显示“数据待核验”，保留止损人工核验提示。
- 缺成本：方向降级，但只要止损和目标有效，仍可展示风险边界。
- 缺止损或目标：不生成完整区间，明确写“缺 stop_loss”或“缺 target_price”。
- 止损不低于目标、当前价非法或股数非法：标记输入冲突，不生成伪精确结果。
- 飞书超过长度限制：优先保留硬风控、持仓动作和精简预测；详细口径留在 Obsidian。

## 7. 测试设计

采用测试先行，至少覆盖：

1. 三只正常持仓能够生成方向、区间、验证信号和风险边界。
2. 有效收盘价跌破止损时，首屏硬风控和“预测失效”同时出现。
3. 陈旧行情不能生成确定方向或伪精确区间。
4. 缺止损、缺目标和非法边界分别输出具体数据缺口。
5. 组合悲观、基准、乐观金额及百分比计算正确。
6. 无持仓时不显示空预测表。
7. 飞书摘要继续包含“一至四”主区块且不超过 3000 字。
8. 既有持仓动作、预算阻断、研究分层和硬止损回归测试全部通过。

## 8. 验证与交付

实现后依次执行：

1. 新增预测纯函数和报告渲染单元测试。
2. 运行 `backend/tests/test_daily_report_delivery.py`。
3. 运行项目全量 pytest 和 Ruff。
4. 使用临时 `CONGXI_PORTFOLIO_PATH`、`CONGXI_CANDIDATE_POOL_PATH`、`CONGXI_REPORT_ARCHIVE_DIR` 生成隔离报告。
5. 核对飞书摘要长度、Obsidian 完整报告、预测审计字段和硬止损优先级。
6. 不推送飞书、不修改真实持仓、不重启生产服务，除非用户另行授权。

## 9. 本轮边界

- 不自动下单。
- 不修改真实持仓、成交或止损计划。
- 不把情景区间表述为概率预测。
- 不引入未经回测证明的新技术指标。
- 不以本轮规则区间冒充历史校准后的预测模型。
- 本轮产出的结构化预测结果可进入后续预测账本，用于统计命中率和校准下一版模型。
